# Amigo API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrar os 22 contratos do Amigo à configuração, agenda, CRM e IA do Deskcomm, com token configurável na aplicação.

**Architecture:** Amigo é autoridade para novas consultas quando ativado. Um adaptador tipado centraliza os contratos; serviços autenticados compartilhados pelas telas e tools mantêm vínculos, recibos e projeções locais sem publicar no Google. Módulo opcional provisionado no próprio banco.

**Tech Stack:** Next.js 16, TypeScript 6, React 19, Zod 4, Supabase/Postgres, Vitest, componentes existentes; nenhuma dependência nova.

**Spec:** `docs/superpowers/specs/2026-11-06-amigo-api-design.md`, aprovado pelo usuário em 06/11/2026.

## Global Constraints

- Origem fixa `https://amigobot-api.amigoapp.com.br`, Bearer somente no servidor.
- Uma clínica por instalação; organização e papel resolvidos pela sessão/contexto confiável.
- Token cifrado e não devolvido ao navegador; nenhuma chamada real autenticada sem configuração posterior.
- Não repetir mutação com resultado incerto; não publicar projeções Amigo no Google.
- Configuração ausente não interrompe a aplicação. Histórico local não é migrado automaticamente.
- Consultas externas sem vínculo não geram contatos, negócios ou mensagens; bootstrap não reproduz automações.
- Os valores operacionais propostos no desenho são 5 minutos por sincronização e janela -7/+90 dias, limitada em lotes.

## Review Focus

- Telefone compartilhado: nunca vincular automaticamente o primeiro paciente (Tarefas 3/4/6).
- Timeout depois de gravação remota: resultado incerto bloqueia repetição e exige reconciliação (Tarefas 1/3).
- Token trocado de conta: IDs antigos não são reutilizados em nova conexão (Tarefas 2/3).
- Compromisso Amigo projetado como pendente: cron local não o expira nem Google o publica (Tarefas 5/7).
- Ordem de chegada e datas sem offset: preservar turno e hora civil no fuso da clínica (Tarefas 1/4/5).

## File Structure and Interfaces

- `lib/amigo/contracts.ts`: enum de operações, inputs Zod e tipos de transporte, sem segredo/Node.
- `lib/amigo/transport.ts`: `requestAmigo(token, operation, input, options?) -> Promise<{ data: unknown; status: "success" }>`; `AmigoError` com `code`, `status`, `uncertain`, mensagem segura.
- `lib/amigo/store.ts`: configuração cifrada e provisionamento, somente servidor.
- `lib/amigo/service.ts`: `executeAmigo(ctx, operation, input, operationKey?)`; contexto `{organizationId,actor,requestId,contactId?,conversationId?}`. Retorno `{data, operation_id?, local_appointment_id?, uncertain?}`. Rotas/MCP usam esta fronteira.
- `lib/amigo/operations.ts`: recibos duráveis e reconciliação, sem retentativa cega.
- `lib/amigo/projection.ts`: vínculo e projeção sem criação duplicada; reusa timeline/funil com bootstrap sem efeitos.
- `lib/amigo/agenda.ts`: despacho/normalização do provedor para consumidores de agenda.
- `app/api/v1/integrations/amigo/route.ts`: GET metadados, PUT configuração, DELETE desconexão, admin.
- `app/api/v1/integrations/amigo/test/route.ts`: POST teste somente leitura, admin.
- `app/api/v1/integrations/amigo/execute/route.ts`: POST operação nomeada, guard por capacidade.
- `app/api/v1/integrations/amigo/links/route.ts`: POST vínculo explícito de paciente/contato/negócio.
- `app/app/integrations/amigo/`: configuração e console de operação com formulários de negócio.
- `lib/mcp/tools/amigo.ts` + catálogo: operações para IA com escopo no contato e mesma fronteira de domínio.
- Schema: metadados `amigo_connections`, segredo separado `amigo_credentials`, vínculos `amigo_patient_links`, projeções `amigo_appointment_links`, recibos `amigo_operations`, todos escopados por organização/conexão. Tabelas específicas criadas por função provisionadora service-role-only. Datas e IDs numéricos externos preservados.

### Task 2: Persistência, credencial e configuração

**Files:** migration criada pela CLI, baseline, `lib/amigo/store.ts`, testes de banco e configuração.
**Produces:** `AmigoSafeConfig`, `getAmigoConfig(orgId)`, `saveAmigoConfig(orgId, actorId, input)`, `disconnectAmigo(orgId)`, `loadAmigoConnection(orgId)` com token somente no servidor, `provisionAmigo()`.
**Config:** `{configured,active,connection_id,token_last4,validated_at,default_place_id,timezone,allow_same_day?,months_ahead?,reminders_enabled,last_sync_at,last_error}`; input aceita `token?`, `active?`, `default_place_id?`, `timezone?`, opções da oferta e lembretes. Token novo exige novo teste e nova identidade de conexão.

- [ ] Testes RED: segredo negado para anon/authenticated; metadados de outra organização inacessíveis; configuração não permite ativar sem validação/unidade/fuso.
- [ ] Implementar SQL opcional idempotente com grants explícitos, RLS e FKs compostas para impedir vínculos entre clínicas; função provisionadora `fn_provision_amigo`, somente service_role.
- [ ] Cifrar com infraestrutura existente; erro explícito quando chave ausente. Salvar/testar token com `GET /places`, não criar entidades. Substituição cria conexão nova e desativa a antiga sem apagar histórico.
- [ ] Rodar teste de banco isolado e teste do store; aplicar no Supabase de desenvolvimento, sem tocar projetos existentes. Commit.

### Task 3: Domínio, recibos, vínculos e rotas

**Files:** `lib/amigo/{service,operations,projection}.ts`, rotas Amigo, testes irmãos.
**Consumes:** contratos/transporte da Tarefa 1 e store/SQL da Tarefa 2.
**Produces:** `executeAmigo` e vínculo explícito utilizados pela UI, IA e sincronização; retorno terminal/recibo estável.

- [ ] Testes RED de replay concorrente, resultado remoto incerto, autorização antes do segredo, contato de outra clínica, paciente ambíguo e falha de projeção após sucesso externo.
- [ ] Implementar reserva durável com hash de payload, estado antes da chamada e reconciliação; nenhuma expiração automática de resultado incerto. Cancelar/remarcar mantém o ID externo.
- [ ] Projeção única de compromisso com IDs externos, status remoto e data/hora; vínculos opcionais e explícitos para destinatário/negócio. Bootstrap apenas estabelece estado, sem automações.
- [ ] Rotas finas com Zod, wrappers, guard de suporte, RBAC e auditoria sanitizada. UI não recebe token em GET. Operações de lista global/aniversariantes exigem gestão.
- [ ] Rodar testes de serviços/rotas e invariantes de banco; esperado bloqueios/replay corretos e ausência de token. Commit.

**Consumes:** `executeAmigo` com contexto confiável; mesmos resultados usados pela UI.
