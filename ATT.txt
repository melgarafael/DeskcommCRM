# 🚀 PROMPT: DeskcommCRM → Sistema de Gestão Comercial Completo (Estilo Mercos)

> **Base de código:** `https://github.com/melgarafael/DeskcommCRM`  
> **Stack atual:** Next.js 16 + React 19 + TypeScript + Tailwind + shadcn/ui + Supabase (Postgres + RLS + Auth + Storage + Realtime) + WAHA + Vercel AI SDK + Zod  
> **Objetivo:** Evoluir o DeskcommCRM de "CRM de atendimento por WhatsApp com IA" para um **Sistema Operacional de Vendas completo** — do primeiro contato à entrega da mercadoria — mantendo 100% das funcionalidades existentes (WhatsApp, IA, automações, webhooks, multi-tenant, LGPD, self-host) e adicionando módulos de **pedidos comerciais, nota fiscal, expedição/logística, catálogo de produtos, dashboards executivos, recuperação de clientes, e-commerce B2B interno, e gestão de força de vendas**.

---

## 1. VISÃO GERAL DO PRODUTO

O sistema deve ser uma **plataforma unificada de vendas B2B** que atenda desde a prospecção (via WhatsApp, IA, formulários web) até a expedição da mercadoria e emissão de nota fiscal. Ele deve funcionar como um **"vendedor digital"** para a empresa: qualifica leads, converte em pedidos, gerencia estoque, controla políticas comerciais, emite documentos fiscais, organiza a logística de entrega e recupera clientes inativos automaticamente.

**Princípios não-negociáveis:**
- Manter multi-tenancy com RLS, LGPD by-design, audit log append-only
- Manter self-hosted com instalação em 1 comando (`hostgator-setup-kit`)
- Manter agentes de IA como "assignees de primeira classe" que operam o CRM via MCP
- Manter WhatsApp (WAHA + Meta Cloud API) como canal nativo
- Design moderno, limpo, inspirado no Mercos (tons de azul escuro, branco, cinza claro, verde para sucesso, laranja para alertas)
- Tudo integrado: nenhum dado duplicado, nenhuma tela isolada

Este é o coração do sistema. Deve ser robusto, rápido e visual.

#### 5.1 Tela de Pedidos (Lista)

- **Badges de origem visuais e distintas:**

- **Status do pedido:** Rascunho → Em Análise → Aprovado → Faturado → Expedido → Entregue → Cancelado
- **Ações em massa:** Aprovar, cancelar, gerar NF, expedir, exportar PDF

#### 5.2 Tela de Novo Pedido / Edição
Interface dividida em 3 colunas (inspirada no Mercos):
- **Coluna 1 (esquerda, 20%):** Busca de cliente (autocomplete), dados do cliente selecionado, condição de pagamento, tabela de preço aplicada, observações gerais
- **Coluna 2 (centro, 50%):** Busca de produtos (com foto thumbnail no autocomplete), lista de itens do pedido com: produto, quantidade, preço unitário, desconto (%), subtotal. Permitir arrastar para reordenar. Cálculo automático de total.
- **Coluna 3 (direita, 30%):** Resumo do pedido — subtotal, descontos, impostos (ICMS, IPI, etc.), frete, total. Botões de ação: Salvar Rascunho, Finalizar Pedido, Compartilhar PDF.

**Regras de negócio:**
- Aplicar políticas comerciais automaticamente (desconto máximo por vendedor, tabela de preço do cliente)
- Bloquear pedido se estoque insuficiente (com opção de override para admin)
- Bloquear pedido se cliente exceder limite de crédito
- Histórico de versões do pedido (quem alterou, quando, o que mudou — audit log)

#### 5.3 Pedido Detalhado para Impressão (Novo)

- **Opções:** Visualizar PDF, Baixar PDF, Enviar por e-mail/WhatsApp, Imprimir direto

## 4. FLUXOS DE TRABALHO DETALHADOS

### Fluxo 1: Venda Completa (WhatsApp → Pedido → NF → Expedição)
1. Cliente manda mensagem no WhatsApp
2. IA atende, qualifica, monta carrinho na conversa
3. Cliente confirma → IA cria pedido (origem: WhatsApp/IA)
4. Vendedor recebe notificação, revisa e aprova
5. Sistema gera NF-e automaticamente (ou manualmente)
6. Pedido vai para fila de expedição
7. Expedidor cria carga/romaneio com vários pedidos
8. Motorista entrega → comprovante de entrega
9. Cliente recebe NF-e por e-mail/WhatsApp

### Fluxo 2: Recuperação de Cliente Inativo
1. Sistema identifica cliente sem compra há 60 dias
2. Automação dispara: IA envia WhatsApp personalizado com oferta
3. Cliente não responde em 3 dias → E-mail automático
4. Cliente não responde em 7 dias → Tarefa criada para vendedor ligar
5. Cliente faz pedido → marcado como "Recuperado", campanha atualiza métricas

### Fluxo 3: Importação em Massa
1. Admin acessa Configurações → Importações
2. Seleciona tipo: Clientes ou Produtos
3. Faz upload do Excel
4. Sistema mostra preview com mapeamento de colunas
5. Valida CNPJs duplicados (clientes) ou SKUs duplicados (produtos)
6. Admin confirma → importação em background com progresso
7. Log de resultado: quantos importados, quantos erros, quais linhas

### Fluxo 4: Pedido pelo Portal B2B
1. Cliente acessa portal com CNPJ + senha
2. Vê catálogo com preços dele (tabela específica)
3. Adiciona produtos ao carrinho
4. Finaliza pedido → entra no sistema como "B2B"
5. Vendedor recebe notificação para aprovação
6. Após aprovação, segue fluxo normal de faturamento

## 5. REGRAS DE NEGÓCIO E VALIDAÇÕES

- **SKU único por tenant:** Não permitir SKU duplicado dentro do mesmo tenant
- **Cliente único por CNPJ/CPF:** Alertar se CNPJ já cadastrado na importação
- **Política de desconto:** Se vendedor aplicar desconto acima do permitido, pedido vai para "Em Análise" (aprovador)
- **Estoque negativo:** Configurável por tenant — permitir ou bloquear
- **Limite de crédito:** Bloquear pedido se soma de pedidos em aberto + novo pedido > limite
- **Histórico de preços:** Registrar todo histórico de alteração de preço de produto (audit)
- **Numeração de pedido:** Sequencial por tenant (ex: PED-0001, PED-0002)
- **NF-e:** Não permitir cancelar NF-e após 24h sem justificativa (regra fiscal)
